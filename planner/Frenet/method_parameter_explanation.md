# 规划器及六种方法的参数设置说明

## 1 引言

为保证本文实验结果的可复现性与方法比较的公平性，有必要对当前规划器及其六种方法变体所采用的参数体系、实际生效方式及其设置依据进行系统说明。需要特别指出的是，当前工程中的参数并非完全由 JSON 配置文件单独决定，而是由**配置文件参数**与**代码级策略开关**共同构成。前者主要决定采样精度、预测时域、风险阈值和代价权重等数值；后者则决定联合场景集的截取方式、共享段是否自适应分支、是否执行后续可恢复性约束以及是否退化为单轨迹规划等关键算法机制。

因此，若仅阅读 `planning_fast.json`、`contingency.json` 等配置文件，而忽略 `frenet_planner.py` 中的方法分支逻辑，往往会对“实际生效参数”产生误判。本文档按照高水平科技期刊论文的写作规范，对当前代码中真实参与规划决策的参数作出统一梳理，并进一步解释各参数的工程动机与方法学含义。


## 2 参数来源与生效层次

当前六种方法的参数来源可以划分为三个层次：

### 2.1 基础数值配置层

该层由以下文件给出：

- `planner/Frenet/configs/planning_fast.json`
- `planner/Frenet/configs/contingency.json`
- `planner/Frenet/configs/risk.json`
- `planner/Frenet/configs/weights.json`

其中：

- `planning_fast.json` 负责共享段（shared segment）的基础采样参数；
- `contingency.json` 负责分支段（contingent segment）的基础采样参数以及自适应分支配置；
- `risk.json` 给出风险约束与风险评估模式；
- `weights.json` 给出轨迹代价函数的权重设置。

### 2.2 代码级覆盖层

在 `planner/Frenet/frenet_planner.py` 中，部分采样参数被直接覆盖。例如：

- 共享段横向采样并未直接使用 `planning_fast.json` 中解析后的 `d_list`，而是被固定为  
  \[
  d \in \{-1.75,-1.1667,-0.5833,0,0.5833,1.1667,1.75\}
  \]
  即 `np.linspace(-1.75, 1.75, 7)`；
- 分支段横向采样亦未直接使用 `contingency.json` 中的 `d_list`，而是被固定为  
  \[
  d \in \{-1.75,-1.05,-0.35,0.35,1.05,1.75\}
  \]
  即 `np.linspace(-1.75, 1.75, 6)`。

因此，后文在介绍参数时，将统一采用“**实际生效参数**”而非“名义配置参数”。

### 2.3 方法逻辑层

六种方法的根本差异并不体现在基础数值参数上，而体现在以下方法开关上：

1. 是否采用可信联合场景集（credible joint set）；
2. 是否采用自适应分支时刻；
3. 是否退化为单条共享轨迹；
4. 是否显式施加后续可恢复性约束；
5. 共享段风险评估是针对全部模式、最大后验模式还是可信模式集合。

这些逻辑主要由各方法分支中的 `planner/Frenet/frenet_planner.py` 决定。


## 3 当前规划器的公共参数

本节介绍六种方法共享的基础规划器参数。除非在后续各方法小节中另有说明，这些参数在六种方法中保持一致。

### 3.1 规划模式与运行环境参数

当前规划器采用 `risk` 模式运行，其含义是：

1. 规划过程中显式计算多障碍物碰撞风险；
2. 轨迹排序不仅依赖几何可行性，还依赖风险相关约束；
3. 最终轨迹代价函数中包含风险项与路径偏离项。

基础运行参数如下：

| 参数 | 数值 | 作用 |
|---|---:|---|
| 运行模式 | `risk` | 启用风险评估与风险约束 |
| 场景离散步长 | 0.1 s | 统一的轨迹离散与预测更新步长 |
| 车辆类型 | `bmw_320i` | 车辆动力学与几何参数来源 |
| 可视化 | 默认关闭 | 批量评测时减少不必要的时间开销 |
| 计时统计 | 开启 | 用于记录单周期计算时间指标 |

此外，规划器默认传感器半径为 `11155.0 m`。该值远大于当前交叉口场景的空间尺度，实质上相当于**全场景感知**。这种设定的目的并非模拟真实传感器，而是为了避免“感知截断”干扰方法对比，使实验更集中于**规划机制本身**。


### 3.2 多模态预测与行为信念参数

当前代码已不再沿用基于可达 lanelet sequence 的 left/right/straight 模式，而是将每个动态障碍物统一表示为两个行为模式：

- `yield`
- `challenge`

这是当前规划器最重要的建模假设之一。其理由在于：本文关注的是交叉口场景中的博弈式让行决策，而非路径类别识别本身。在障碍物仅沿既有道路中心线直行的前提下，真正决定规划风险结构的并不是“左转/右转/直行”这类拓扑标签，而是“让行/抢行”这类**交互意图**。

对应参数如下：

| 参数 | 数值 | 说明 |
|---|---:|---|
| 每障碍物模式数 | 2 | `yield/challenge` |
| 初始先验 | [0.5, 0.5] | 对两类意图不预设偏见 |
| 遗忘因子 | 0.72 | 保留历史 belief，但避免过强惯性 |
| 中性先验回拉 | 0.08 | 防止 posterior 过早塌缩为 0/1 |
| 预测时域 | 27 步 | 由 \(\max(1.4,2.6)/0.1 + 1\) 决定 |

其中，预测时域设置为 27 个离散点，其工程理由是：

1. 共享段最大名义长度为 1.4 s；
2. 分支段名义长度为 2.6 s；
3. 规划阶段必须至少覆盖更长的那一段，否则共享规划与分支规划将缺乏统一的未来信息基础。

因此，预测时域统一取
\[
\left\lfloor \frac{\max(1.4,\,2.6)}{0.1} \right\rfloor + 1 = 27.
\]

这种处理有利于保证：

- 共享段与分支段基于同一预测窗口评估；
- 不同方法之间在预测信息量上保持一致；
- 自适应分支不会因预测长度不足而产生额外偏差。


### 3.3 共享段轨迹采样参数

共享段的名义配置来自 `planning_fast.json`，但其实际生效参数应按代码执行结果理解。

#### 3.3.1 名义配置

| 参数 | 名义数值 |
|---|---:|
| 名义共享时域上限 | 1.4 s |
| 速度采样方式 | `linspace` |
| 末速度样本数 | 7 |
| 名义横向采样范围 | \([-1.8,1.8]\) |
| 名义横向采样个数 | 10 |
| 离散步长 | 0.1 s |
| 高低速切换阈值 | 3.0 m/s |

#### 3.3.2 实际生效参数

共享段在运行时的有效采样参数为：

| 参数 | 实际生效值 |
|---|---:|
| 共享时域 | 由方法决定（详见第 4 节） |
| 速度采样方式 | `linspace` |
| 末速度样本数 | 7 |
| 横向采样点 | `np.linspace(-1.75, 1.75, 7)` |
| 离散步长 | 0.1 s |
| 高低速切换阈值 | 3.0 m/s |

这里将横向采样压缩到 7 个点，主要出于以下考虑：

1. 当前交叉口实验以纵向博弈为主，横向机动自由度相对有限；
2. 过密的横向采样会显著提高候选轨迹数量，导致多场景规划时间上升；
3. 适度缩减横向采样密度，有助于将计算预算优先分配给不确定场景分支。

换言之，该设定体现的是一种**将计算资源从横向冗余采样转移到交互不确定性处理**的设计思想。


### 3.4 分支段轨迹采样参数

分支段配置来自 `contingency.json`。其名义与实际参数如下。

#### 3.4.1 名义配置

| 参数 | 名义数值 |
|---|---:|
| 分支段时域 | 2.6 s |
| 速度采样方式 | `linspace` |
| 末速度样本数 | 5 |
| 名义横向采样范围 | \([-2.0,2.0]\) |
| 名义横向采样个数 | 3 |
| 离散步长 | 0.1 s |
| 高低速切换阈值 | 3.0 m/s |

#### 3.4.2 实际生效参数

| 参数 | 实际生效值 |
|---|---:|
| 分支段时域 | 2.6 s |
| 速度采样方式 | `linspace` |
| 末速度样本数 | 5 |
| 横向采样点 | `np.linspace(-1.75, 1.75, 6)` |
| 离散步长 | 0.1 s |
| 高低速切换阈值 | 3.0 m/s |

分支段采用 2.6 s 的较长时域，主要考虑如下：

1. 共享段只负责在不确定性尚未充分分离前保持策略一致；
2. 一旦进入分支段，各模式下的动作差异需要在后续一段时间内充分展开；
3. 若分支段时域过短，则让行/抢行两类意图的行为差异无法被轨迹优化真正“吸收”，从而削弱 contingent planning 的意义。

因此，2.6 s 并非任意取值，而是兼顾以下三点后的结果：

- 能覆盖交叉口冲突区前后的主要交互过程；
- 又不至于使单周期优化过于昂贵；
- 能够支撑可恢复性分析对“未来继续分支是否可行”的判断。


### 3.5 风险约束参数

风险配置来自 `risk.json`，当前关键参数如下：

| 参数 | 数值 | 说明 |
|---|---:|---|
| 风险聚合方式 | `max` | 以轨迹上的最大风险表征整条轨迹 |
| 最大可接受风险 | 0.05 | 单轨迹风险阈值 |
| 最大可接受轨迹级碰撞概率上界 | 0.20 | 额外轨迹级安全边界 |
| 多重 cost 函数模式 | `false` | 不采用低有效性轨迹的特殊 cost 重构 |
| 遮挡模型 | 关闭 | 当前实验聚焦交互规划，不强调视觉遮挡 |
| 风险仪表盘 | 关闭 | 减少评测时开销 |
| 碰撞报告 | 开启 | 保留关键失败信息 |

这些阈值的设置体现了“**先安全筛选，再经济排序**”的总体原则。具体而言：

1. `max_acceptable_risk = 0.05` 用于将显著高风险轨迹剔除；
2. `max_acceptable_trajectory_collision_prob_upper_bound = 0.20` 进一步从轨迹级碰撞事件角度约束方案；
3. 在此基础上，代价函数才对剩余可行轨迹进行细粒度排序。

这是一种典型的层级式规划结构：  
**风险阈值决定“能不能选”，代价函数决定“选哪一个”。**


### 3.6 代价函数权重参数

当前默认权重来自 `weights.json`，其有效值为：

| 代价项 | 权重 |
|---|---:|
| bayes | 33.3 |
| equality | 33.3 |
| maximin | 33.3 |
| ego | 10.0 |
| risk_cost | 1.0 |
| dist_to_global_path | 1.0 |
| velocity | 0.0 |
| visible_area | 0.0 |
| lon_jerk | 0.0 |
| lat_jerk | 0.0 |
| travelled_dist | 0.0 |
| dist_to_goal_pos | 0.0 |
| dist_to_lane_center | 0.0 |
| responsibility | 0.0 |

由此可见，当前规划器的排序重点并不是传统意义上的舒适性或速度最优，而是：

1. 风险分项（Bayes、公平性、Maximin、自车风险）；
2. 与全局参考路径的一致性。

这种设定的原因在于，本文研究对象是交叉口不确定交互规划问题。对于该问题而言，最关键的性能不是“横向是否绝对平顺”，而是：

- 能否在不确定场景下保持安全；
- 能否在安全前提下维持合理通行效率；
- 能否避免轨迹偏离既定通行意图。

因此，将权重重点放在风险项与参考路径一致性上，具有明确的方法学合理性。


## 4 六种方法的参数化差异

在公共参数一致的前提下，六种方法的主要差异体现在以下四个方面：

1. 联合场景集采用“可信子集”还是“全部场景”；
2. 共享段是自适应分支、固定分支还是整段共享；
3. 是否保留 contingent branching；
4. 是否强制满足可恢复性约束。

为便于比较，表 1 先给出方法级参数摘要。

### 表 1 六种方法的关键方法级参数

| 方法 | 联合场景集 | 共享段时域策略 | 是否保留 contingent 分支 | 是否施加可恢复性约束 |
|---|---|---|---|---|
| Ours | 可信联合场景集 | 自适应分支 | 是 | 是 |
| Fixed-CP | 可信联合场景集 | 固定 1.4 s | 是 | 是 |
| Robust-Single | 全联合场景集 | 全时域单共享轨迹 | 否 | 否 |
| MLE | 最大后验单场景 | 全时域单共享轨迹 | 否 | 否 |
| Ours w/o CS | 全联合场景集 | 自适应分支 | 是 | 是 |
| Ours w/o Rec | 可信联合场景集 | 自适应分支 | 是 | 否 |


## 5 各方法的具体参数与设置依据

### 5.1 Ours（本文方法）

本文方法采用以下关键参数：

| 参数 | 数值 / 机制 |
|---|---|
| 联合场景集 | 可信联合场景集 |
| 可信水平参数 | \(\alpha = 0.05\) |
| 自适应分支 | 开启 |
| 候选分支时刻 | 0.4 s 至 1.4 s，步长 0.1 s |
| 分离度阈值 | 1.0 |
| 可恢复性约束 | 开启 |

其中，可信联合场景集通过如下原则构造：在所有联合模式中，按后验概率从高到低排序，选取最少个模式，使其累计概率质量不少于 \(1-\alpha = 0.95\)。该参数设计的考虑如下：

1. \(\alpha = 0.05\) 对应统计上常用的 95\% 可信覆盖水平；
2. 可有效剔除后验极低、但组合数目庞大的尾部场景；
3. 在维持主要不确定性质量的同时显著降低组合爆炸。

自适应分支时刻设置为 `0.4:0.1:1.4 s`，其原因是：

1. 小于 0.4 s 时，场景差异尚未充分显现，过早分支缺乏意义；
2. 大于 1.4 s 时，共享决策时间过长，可能导致后续修正空间不足；
3. 0.1 s 与规划离散步长一致，可保证实现简洁且便于解释。

同时，本文方法要求一条共享段在进入最终候选集之前，必须对可信场景集中的全部模式都存在对应可行分支。该约束体现的是**风险可分离之后仍须保持后续控制可恢复性**的思想，是本文方法区别于普通 contingent planning 的核心。


### 5.2 Fixed-CP

Fixed-CP 方法的公共参数与本文方法保持一致，但做出如下固定化处理：

| 参数 | 数值 / 机制 |
|---|---|
| 联合场景集 | 可信联合场景集 |
| 分支时刻 | 固定为 1.4 s |
| 自适应分支 | 关闭 |
| 可恢复性约束 | 开启 |

该方法的设置目的是：**隔离“自适应分支时刻选择”这一模块的增益**。通过将分支时刻固定在共享规划的名义上限 1.4 s，可以构造一个公平基线，使其与本文方法在下列方面完全一致：

- 联合场景处理方式一致；
- 分支段规划机制一致；
- 可恢复性约束一致；
- 成本函数与风险阈值一致。

唯一不同之处仅在于：Fixed-CP 不再根据场景可分离性提早分支。由此可直接评估“自适应分支时刻选择”本身是否有助于提升安全性、通行效率与实时性。


### 5.3 Robust-Single

Robust-Single 方法的关键参数如下：

| 参数 | 数值 / 机制 |
|---|---|
| 联合场景集 | 全联合场景集 |
| 共享段时域 | 2.6 s（全时域） |
| contingent 分支 | 不生成 |
| 可恢复性约束 | 不施加 |
| 共享段风险模式 | `mode_num = 100`，即按全部模式评估 |
| belief 加权 | 关闭 |

这里的“2.6 s 全时域共享轨迹”意味着：规划器在整个规划窗口内只优化一条统一轨迹，而不允许在未来某一时刻根据场景差异分叉。因此该方法代表的是一种**整段单轨迹鲁棒规划**思想。

其设置依据如下：

1. 采用全联合场景集，是为了让这条共享轨迹同时面对所有可能场景；
2. 不再做 contingent branching，是为了构造与本文方法相对的“无分支鲁棒”基线；
3. 将共享时域扩展为 2.6 s，是因为既然不允许后续分支，就必须在整个决策区间内一次性满足所有场景约束。

这类方法通常具有更强的保守性。其理论优势在于，对场景切换不敏感；其潜在代价在于，容易因为同时满足过多场景而导致可行域收缩、通行效率下降，甚至出现“平均看起来安全、局部却更难协调”的现象。


### 5.4 MLE

MLE 方法的参数如下：

| 参数 | 数值 / 机制 |
|---|---|
| 联合场景集 | 仅取最大后验联合场景 |
| 共享段时域 | 2.6 s（全时域） |
| contingent 分支 | 不生成 |
| 可恢复性约束 | 不施加 |
| 共享段风险模式 | 仅针对最大后验联合模式 |
| belief 加权 | 关闭 |

该方法的思想是：在每个规划周期，仅根据当前后验概率最大的联合场景执行确定性规划，而不显式保留其余低概率模式。其作用在于构造一个“**最大似然确定性规划**”基线。

设置该方法的原因主要有三点：

1. 它代表许多传统单场景规划器的基本工作方式；
2. 它能反映“忽略场景尾部不确定性”时的效率上限；
3. 它可用于验证：本文方法的优势究竟来自“更精细的不确定性保留”，还是仅仅来自更保守的风险阈值。

MLE 的优点通常是计算代价较低、决策果断；但其局限在于，对后验分布中的次高概率场景缺乏显式防御能力。因此，在场景尚未充分分离的阶段，MLE 更容易出现误判性激进决策。


### 5.5 Ours w/o CS

Ours w/o CS 的参数设置如下：

| 参数 | 数值 / 机制 |
|---|---|
| 联合场景集 | 全联合场景集 |
| 自适应分支 | 开启 |
| 候选分支时刻 | 0.4 s 至 1.4 s，步长 0.1 s |
| 分离度阈值 | 1.0 |
| 可恢复性约束 | 开启 |

该方法与本文方法的唯一区别在于：**不再使用可信联合场景集，而是直接保留全部联合模式**。因此，它是检验“可信场景集截断”是否必要的核心消融实验。

设置这一方法的目的在于回答如下问题：  
在保持自适应分支与可恢复性约束均存在的前提下，若不进行概率质量截断，是否一定更安全、更稳健？

从理论上看，答案并不一定。因为：

1. 全场景集会引入大量极低概率模式；
2. 这些模式会额外收缩共享段可行域；
3. 由此可能迫使规划器过度保守，甚至削弱原本高概率场景下的可恢复性。

因此，Ours w/o CS 的设置并非只是“更多考虑一些场景”，而是在测试：  
**概率截断是否能在风险覆盖与可行域保留之间实现更优平衡。**


### 5.6 Ours w/o Rec

Ours w/o Rec 的参数如下：

| 参数 | 数值 / 机制 |
|---|---|
| 联合场景集 | 可信联合场景集 |
| 可信水平参数 | \(\alpha = 0.05\) |
| 自适应分支 | 开启 |
| 候选分支时刻 | 0.4 s 至 1.4 s，步长 0.1 s |
| 分离度阈值 | 1.0 |
| 可恢复性约束 | 关闭 |

该方法与本文方法唯一不同之处在于：虽然仍然计算可信场景集并仍然生成 contingent branches，但在最终 plan 筛选时，不再要求共享段必须对所有可信模式都存在后续可行分支。

换言之，它保留“什么时候分支”的优化，但移除了“分支之后能否继续恢复”的强约束。因此它回答的问题是：

> 若只依据场景可分离性选择分支时刻，而不进一步约束后续分支的可行恢复能力，性能会怎样变化？

该消融具有明确意义：

1. 如果与本文方法结果几乎一致，说明 recoverability 约束贡献有限；
2. 如果在高风险样本中出现明显退化，则说明仅有“早分支”还不够，必须进一步保证“后续仍可控”。


## 6 当前参数体系的整体设计逻辑

综合上述分析，当前规划器及六种方法的参数设置遵循以下总体原则。

### 6.1 统一基础采样参数，保证比较公平

六种方法在以下方面保持一致：

- 车辆模型与场景离散步长；
- 共享段速度采样密度；
- 分支段速度采样密度；
- 风险阈值；
- 成本函数权重；
- 障碍物行为模式定义与 belief 更新方式。

这保证了实验比较真正体现的是**方法机制差异**，而非简单的“采样更密 / 风险更松 / 权重更偏”。

### 6.2 将核心差异集中到三类方法学开关

六种方法之间的差异被有意压缩到三个核心问题上：

1. **场景集保留多少**：可信场景集还是全场景集；
2. **何时分支**：固定、全时域共享还是自适应选择；
3. **是否要求后续可恢复**：只要当前可行，还是要求未来所有可信模式下均有延续解。

这种设计使得各方法之间具有清晰的因果可解释性。

### 6.3 在实时性与鲁棒性之间追求平衡

从参数组合可以看出，本文方法并非简单追求“最保守”：

- 若只追求鲁棒，可直接采用全场景集 + 全时域单共享轨迹；
- 若只追求计算快，可直接采用 MLE 单场景规划；
- 若只追求形式上的早分支，可直接固定较短共享时域。

本文方法的参数设计本质上是在寻求如下平衡：

\[
\text{安全覆盖} \;+\; \text{适度截断} \;+\; \text{可恢复性保证} \;+\; \text{可接受的计算负担}
\]

这也是其区别于其他五种比较方法的根本所在。


## 7 结论

当前实验体系中，六种方法在基础数值参数上高度一致；其性能差异主要来自方法级参数，即联合场景集截取策略、共享段时域策略以及可恢复性约束是否启用。就工程实现而言，应特别注意以下两点：

1. 某些横向采样参数在代码中被硬编码覆盖，不能仅依据 JSON 文件理解其真实生效值；
2. 自适应分支、可信场景集与可恢复性约束是六种方法之间最核心的差异来源。

因此，在解释实验结果时，应避免将性能差异简单归因于“采样数不同”或“风险阈值不同”，而应从场景保留策略、共享决策长度与后续恢复能力约束三方面进行分析。只有在这一前提下，本文方法与各基线、消融方法之间的比较才具有严格的方法学意义。
